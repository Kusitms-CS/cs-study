# 9주차 - 정보보호 (9급 공무원 정보보호론 수준)

9급 공무원 시험 「정보보호론」 범위를 기준으로, 자주 출제되는 개념과 비교 포인트 위주로 정리했다.

## 1. 정보보호 개요

### 정보보호의 목표 (보안 3요소, CIA)

| 요소 | 의미 | 위협하는 공격 | 대표 대책 |
| --- | --- | --- | --- |
| 기밀성 (Confidentiality) | 인가된 사용자만 정보를 볼 수 있음 | 도청, 스니핑, 가로채기 | 암호화, 접근통제 |
| 무결성 (Integrity) | 인가된 방법으로만 정보를 변경할 수 있음 | 변조, 위조 | 해시, MAC, 전자서명 |
| 가용성 (Availability) | 필요할 때 정보·서비스를 사용할 수 있음 | DoS/DDoS, 차단 | 이중화, 백업, DDoS 대응 |

추가 요소도 함께 출제된다.

| 요소 | 의미 |
| --- | --- |
| 인증성 (Authenticity) | 사용자·메시지 출처가 진짜임을 확인 |
| 책임추적성 (Accountability) | 행위를 한 주체를 추적할 수 있음 (로그) |
| 부인방지 (Non-repudiation) | 송수신 사실을 나중에 부인할 수 없음 (전자서명) |

### 공격 유형

| 공격 | 내용 | 침해되는 요소 |
| --- | --- | --- |
| 가로채기 (Interception) | 전송 중인 정보를 몰래 획득 | 기밀성 |
| 차단 (Interruption) | 정보 전달을 방해 | 가용성 |
| 변조 (Modification) | 전송 중인 정보를 수정 | 무결성 |
| 위조 (Fabrication) | 다른 사람인 척 정보를 생성 | 무결성(인증성) |

| 구분 | 소극적 공격 (Passive) | 적극적 공격 (Active) |
| --- | --- | --- |
| 특징 | 정보를 변경하지 않음. **탐지가 어려움** → 예방 중심 | 정보를 변경·생성. 탐지는 가능 → 탐지·복구 중심 |
| 예 | 도청(메시지 내용 공개), 트래픽 분석 | 재전송(Replay), 변조, 신분 위장(Masquerade), 서비스 거부 |

트래픽 분석은 암호화되어 내용을 몰라도 **통신 빈도·길이·상대방** 등의 패턴으로 정보를 얻는 공격이다.

### 위험의 구성

```
위험(Risk) = 자산(Asset) × 위협(Threat) × 취약점(Vulnerability)
```

- **자산**: 보호해야 할 대상 (정보, 시스템, 인력)
- **위협**: 자산에 손해를 끼칠 수 있는 원인 (해커, 자연재해)
- **취약점**: 위협이 이용할 수 있는 약점 (패치 안 된 시스템, 약한 비밀번호)
- **정보보호 대책**: 취약점을 줄이거나 위협의 영향을 낮춤

## 2. 암호학

### 기본 용어와 고전 암호

| 용어 | 의미 |
| --- | --- |
| 평문 (Plaintext) | 암호화 전 메시지 |
| 암호문 (Ciphertext) | 암호화된 메시지 |
| 키 (Key) | 암호화·복호화에 쓰는 값 |
| 케르크호프스 원리 | 암호 알고리즘은 공개되어도 **키만 비밀**이면 안전해야 함 |

| 고전 암호 | 방식 | 예 |
| --- | --- | --- |
| 치환 (Substitution) | 문자를 다른 문자로 바꿈 | 카이사르(시저) 암호, 비즈네르 암호, 플레이페어 |
| 전치 (Transposition) | 문자의 **위치(순서)**를 바꿈 | 스키테일 암호, 레일펜스 |

샤논이 제시한 안전한 암호의 성질:

- **혼돈 (Confusion)**: 암호문과 키의 관계를 복잡하게 함 → 치환으로 구현
- **확산 (Diffusion)**: 평문 한 비트의 변화가 암호문 전체에 퍼지게 함 → 전치로 구현

### 대칭키 암호

암호화와 복호화에 **같은 키**를 사용한다. 빠르지만 **키 분배**가 어렵다.

| 구분 | 블록 암호 | 스트림 암호 |
| --- | --- | --- |
| 단위 | 고정 크기 블록 | 비트·바이트 단위 (키 스트림과 XOR) |
| 예 | DES, AES, SEED, ARIA | RC4, LFSR 기반 암호 |

블록 암호의 내부 구조는 두 가지다.

| 구조 | 특징 | 알고리즘 |
| --- | --- | --- |
| Feistel | 블록을 반으로 나눠 라운드 반복. **암호화·복호화 구조가 같음** | DES, 3DES, SEED, Blowfish |
| SPN (Substitution-Permutation Network) | 치환과 전치를 반복. 병렬 처리에 유리 | AES, ARIA(ISPN) |

| 알고리즘 | 블록 크기 | 키 길이 | 라운드 | 구조 | 비고 |
| --- | --- | --- | --- | --- | --- |
| DES | 64비트 | 56비트 | 16 | Feistel | 키가 짧아 현재 안전하지 않음 |
| 3DES | 64비트 | 112/168비트 | 48 | Feistel | DES를 3번 적용 (암호화-복호화-암호화) |
| AES | 128비트 | 128/192/256비트 | 10/12/14 | SPN | 미국 표준(NIST), 원래 이름 Rijndael |
| SEED | 128비트 | 128비트 | 16 | Feistel | 국내 개발 (KISA) |
| ARIA | 128비트 | 128/192/256비트 | 12/14/16 | ISPN | 국내 개발, 국가 표준 |
| HIGHT | 64비트 | 128비트 | 32 | 변형 Feistel | 국내 경량 암호 (IoT·RFID) |
| LEA | 128비트 | 128/192/256비트 | 24/28/32 | ARX | 국내 경량 암호 |

#### 블록 암호 운용 모드

| 모드 | 동작 | 특징 |
| --- | --- | --- |
| ECB | 블록마다 독립적으로 암호화 | 같은 평문 블록 → 같은 암호문 블록. 패턴이 드러나 **가장 취약** |
| CBC | 이전 암호문 블록과 XOR 후 암호화. 첫 블록은 IV 사용 | 가장 널리 쓰임. 암호화는 병렬 불가, 복호화는 병렬 가능 |
| CFB | 이전 암호문을 암호화한 결과와 평문을 XOR | 블록 암호를 스트림 암호처럼 사용 |
| OFB | 이전 **암호화 출력**을 다시 암호화해 키 스트림 생성 | 오류가 전파되지 않음 |
| CTR | 카운터 값을 암호화해 평문과 XOR | **암·복호화 모두 병렬 처리 가능**, 블록 단위 랜덤 접근 가능 |

CFB, OFB, CTR은 블록 암호를 **스트림 암호처럼** 사용하는 모드이다.

### 공개키(비대칭키) 암호

**공개키**와 **개인키** 한 쌍을 사용한다. 키 분배 문제를 해결하지만 대칭키보다 느리다.

| 목적 | 송신자가 사용하는 키 | 수신자가 사용하는 키 |
| --- | --- | --- |
| 기밀성 (암호화) | **수신자의 공개키**로 암호화 | 수신자의 개인키로 복호화 |
| 전자서명 (인증·부인방지) | **송신자의 개인키**로 서명 | 송신자의 공개키로 검증 |

| 알고리즘 | 안전성의 근거 | 용도 |
| --- | --- | --- |
| RSA | **소인수분해**의 어려움 | 암호화, 전자서명 |
| Rabin | 소인수분해 | 암호화 |
| Diffie-Hellman | **이산대수** 문제 | **키 교환** (암호화·서명 아님) |
| ElGamal | 이산대수 | 암호화, 전자서명 |
| DSA | 이산대수 | **전자서명 전용** (미국 DSS 표준) |
| KCDSA | 이산대수 | 전자서명 (국내 표준) |
| ECC | **타원곡선 이산대수** | 암호화, 서명, 키 교환. RSA보다 **짧은 키로 같은 안전성** |

#### 키 개수 계산

n명이 서로 비밀 통신을 할 때 필요한 키의 수:

| 방식 | 필요한 키 수 | n = 100일 때 |
| --- | --- | --- |
| 대칭키 | n(n−1)/2 | 4,950개 |
| 공개키 | 2n (한 사람당 공개키·개인키 한 쌍) | 200개 |

#### RSA 계산

1. 두 소수 p, q 선택 → n = p × q
2. φ(n) = (p − 1)(q − 1)
3. φ(n)과 서로소인 e 선택 (공개키: e, n)
4. e × d ≡ 1 (mod φ(n))인 d 계산 (개인키: d)
5. 암호화 C = Mᵉ mod n, 복호화 M = Cᵈ mod n

예) p = 3, q = 11 → n = 33, φ(n) = 2 × 10 = 20, e = 3이면 3 × 7 = 21 ≡ 1 (mod 20)이므로 d = 7.
평문 M = 4 → C = 4³ mod 33 = 64 mod 33 = **31**.

#### Diffie-Hellman 키 교환

1. 공개 값: 소수 p, 생성자 g
2. A는 비밀 a를 골라 gᵃ mod p를, B는 비밀 b를 골라 gᵇ mod p를 상대에게 보냄
3. 공유 키 K = (gᵇ)ᵃ mod p = (gᵃ)ᵇ mod p = gᵃᵇ mod p

예) p = 23, g = 5, a = 6, b = 15 → A가 보내는 값 5⁶ mod 23 = 8, B가 보내는 값 5¹⁵ mod 23 = 19, 공유 키 19⁶ mod 23 = 8¹⁵ mod 23 = **2**.

인증 과정이 없어 **중간자 공격(MITM)**에 취약하다. 공격자가 A와 B 사이에서 각각 따로 키를 교환하면 둘 다 알아채지 못한다. → 전자서명·인증서로 상대를 인증해야 한다.

### 해시 함수

임의 길이의 입력을 **고정 길이**의 출력(해시값, 메시지 다이제스트)으로 바꾼다.

| 성질 | 의미 |
| --- | --- |
| 역상 저항성 (일방향성) | 해시값 h로부터 h = H(x)인 x를 찾기 어려움 |
| 제2 역상 저항성 (약한 충돌 저항성) | 주어진 x에 대해 H(x) = H(y)인 다른 y를 찾기 어려움 |
| 충돌 저항성 (강한 충돌 저항성) | H(x) = H(y)인 임의의 x, y 쌍을 찾기 어려움 |

| 알고리즘 | 출력 길이 | 비고 |
| --- | --- | --- |
| MD5 | 128비트 | 충돌 발견, 사용 금지 |
| SHA-1 | 160비트 | 충돌 발견, 사용 금지 |
| SHA-256 / SHA-512 (SHA-2) | 256 / 512비트 | 현재 주로 사용 |
| SHA-3 | 224~512비트 | Keccak, 스펀지 구조 |
| HAS-160 | 160비트 | 국내 개발 |
| LSH | 256/512비트 | 국내 개발 |

**생일 공격**: n비트 해시는 약 2^(n/2)번 시도로 충돌 쌍을 찾을 수 있다. (23명만 모여도 생일이 같은 사람이 있을 확률이 50%를 넘는 원리)

비밀번호를 저장할 때는 해시에 **솔트(Salt)**를 더해 같은 비밀번호도 다른 해시값이 되게 한다. 미리 계산된 해시표(레인보우 테이블) 공격을 막는다.

### MAC과 전자서명

| 구분 | 해시 | MAC | 전자서명 |
| --- | --- | --- | --- |
| 키 | 없음 | **대칭키** (공유 비밀키) | **공개키** (송신자 개인키로 서명) |
| 무결성 | O | O | O |
| 메시지 인증 | X | O | O |
| 부인방지 | X | **X** (양쪽이 같은 키를 가짐) | **O** |
| 예 | SHA-256 | HMAC, CBC-MAC | RSA 서명, DSA, ECDSA |

MAC은 송신자와 수신자가 같은 키를 갖고 있어 수신자도 같은 MAC을 만들 수 있으므로 **부인방지가 되지 않는다.**

전자서명은 보통 메시지 전체가 아니라 **메시지의 해시값**에 서명한다(속도 때문).

전자서명의 요건: 위조 불가, 서명자 인증, 부인 방지, 변경 불가, 재사용 불가.

| 특수 전자서명 | 내용 | 활용 |
| --- | --- | --- |
| 은닉 서명 (Blind Signature) | 서명자가 **내용을 모른 채** 서명 | 전자화폐, 전자투표 (익명성) |
| 이중 서명 (Dual Signature) | 두 정보를 연결해 서명. 각 수신자는 필요한 정보만 봄 | **SET** (상점은 주문정보만, 은행은 결제정보만) |
| 그룹 서명 | 그룹 구성원 중 누군가 서명했음만 확인 | 익명 인증 |
| 부인 방지 서명 | 서명자의 협조가 있어야 검증 가능 | |

### PKI (공개키 기반구조)

공개키가 **정말 그 사람의 것인지** 보증하는 체계다. 인증기관이 사용자의 공개키에 서명한 **인증서**를 발급한다.

| 구성 요소 | 역할 |
| --- | --- |
| CA (인증기관) | 인증서 발급·폐지 |
| RA (등록기관) | 사용자 신원 확인 후 CA에 발급 요청 |
| 디렉터리 (LDAP) | 인증서와 폐지 목록 저장·배포 |
| 사용자 | 인증서를 이용해 서명·검증 |

**X.509 인증서**의 주요 항목: 버전, 일련번호, 서명 알고리즘, **발급자**, **유효기간**, **주체(소유자)**, **주체의 공개키**, 확장 영역, CA의 서명.

인증서에는 **소유자의 개인키가 들어 있지 않다.**

| 폐지 확인 방법 | 방식 |
| --- | --- |
| CRL (인증서 폐지 목록) | CA가 폐지된 인증서 목록을 주기적으로 배포. 최신 상태 반영이 늦음 |
| OCSP | 인증서 상태를 **실시간**으로 질의 |

## 3. 접근통제와 인증

### 접근통제의 단계

```
식별 (Identification) → 인증 (Authentication) → 인가 (Authorization) → 책임추적 (Accountability)
   "나는 홍길동이다"        "비밀번호로 증명"          "이 파일 읽기 허용"        "로그 기록"
```

### 사용자 인증 방식

| 유형 | 근거 | 예 |
| --- | --- | --- |
| 지식 기반 (Type 1) | 알고 있는 것 (Something you know) | 비밀번호, PIN |
| 소유 기반 (Type 2) | 가지고 있는 것 (Something you have) | 스마트카드, OTP 토큰, 보안카드 |
| 존재 기반 (Type 3) | 사용자 자신 (Something you are) | 지문, 홍채, 얼굴, 정맥 |
| 행위 기반 | 하는 것 (Something you do) | 서명 동작, 음성, 키보드 입력 패턴 |

**2단계(다중) 인증**은 서로 **다른 유형**을 조합해야 한다. 비밀번호 + PIN은 둘 다 지식 기반이므로 2-Factor 인증이 아니다.

#### 생체 인증의 오류율

| 지표 | 의미 |
| --- | --- |
| FRR (오거부율, Type I 오류) | **본인**을 거부하는 비율 → 편의성 저하 |
| FAR (오수락율, Type II 오류) | **타인**을 수락하는 비율 → 보안상 더 위험 |
| CER / EER (교차 오류율) | FRR과 FAR이 같아지는 지점. **낮을수록 정확한 시스템** |

보안 수준을 높이면 FAR은 낮아지고 FRR은 높아진다(서로 반비례).

#### OTP (일회용 비밀번호)

| 방식 | 내용 |
| --- | --- |
| 시간 동기화 | 일정 시간마다 바뀌는 값. 서버와 시간이 맞아야 함 |
| 이벤트(카운터) 동기화 | 사용할 때마다 증가하는 카운터로 생성 |
| 질의-응답 (Challenge-Response) | 서버가 보낸 질의값으로 응답값 계산 |
| S/Key | 해시 체인을 **역순으로** 사용 |

#### SSO와 Kerberos

**SSO (Single Sign-On)**: 한 번 인증으로 여러 시스템을 이용한다. 편리하지만 인증 정보가 노출되면 모든 시스템이 위험하다(단일 실패 지점).

**Kerberos**: MIT에서 개발한 **대칭키 기반**의 티켓 인증 프로토콜이다.

| 구성 | 역할 |
| --- | --- |
| KDC (Key Distribution Center) | AS와 TGS로 구성 |
| AS (Authentication Server) | 사용자 인증 후 **TGT** 발급 |
| TGS (Ticket Granting Server) | TGT를 받고 서비스별 **서비스 티켓** 발급 |

- 티켓에 **타임스탬프**를 넣어 재전송 공격을 막는다 → 모든 시스템의 **시간 동기화**가 필요하다.
- KDC가 장애를 일으키면 전체 인증이 불가능하다(단일 실패 지점).
- 패스워드 추측 공격에는 여전히 취약하다.

### 접근통제 정책

| 구분 | DAC (임의적) | MAC (강제적) | RBAC (역할 기반) |
| --- | --- | --- | --- |
| 권한 부여 주체 | **객체의 소유자** | **시스템(관리자)**이 보안 등급으로 결정 | 관리자가 **역할**에 권한을 부여 |
| 기준 | 사용자 신원 (ID) | 주체의 비밀취급인가 등급 + 객체의 보안 레이블 | 조직 내 직무(역할) |
| 장점 | 유연함 | 보안성 높음 | 관리 용이, 최소 권한·직무 분리 구현 쉬움 |
| 단점 | 권한이 쉽게 전파되어 통제 어려움 | 경직됨, 구현 복잡 | 역할 설계가 필요 |
| 예 | Unix 파일 권한, ACL | 군사·정부 시스템 | 인사이동이 잦은 기업 |

**접근통제 행렬**의 구현 방식:

- **ACL (접근통제 목록)**: **객체** 기준으로 접근 가능한 주체 목록을 저장 (행렬의 열)
- **CL (권한 목록, Capability List)**: **주체** 기준으로 접근 가능한 객체 목록을 저장 (행렬의 행)

### 접근통제 모델

| 모델 | 목표 | 규칙 |
| --- | --- | --- |
| 벨-라파듈라 (BLP) | **기밀성** (군사용) | **No Read Up** (상위 등급 읽기 금지, 단순 보안 속성)<br>**No Write Down** (하위 등급 쓰기 금지, * 속성) |
| 비바 (Biba) | **무결성** | **No Read Down** (하위 등급 읽기 금지)<br>**No Write Up** (상위 등급 쓰기 금지) |
| 클락-윌슨 (Clark-Wilson) | **무결성** (상업용) | 정형화된 트랜잭션, **직무 분리**, 주체-프로그램-객체의 3원 관계 |
| 만리장성 (Brewer-Nash) | **이해 충돌 방지** | 경쟁 관계에 있는 회사의 정보에 동시에 접근 금지 (금융·컨설팅) |

BLP와 Biba는 규칙이 **정반대**이다. BLP는 "비밀이 아래로 새지 않게", Biba는 "오염된 정보가 위로 올라가지 않게"로 기억한다.

### 보안 원칙

| 원칙 | 내용 |
| --- | --- |
| 최소 권한 (Least Privilege) | 업무에 필요한 최소한의 권한만 부여 |
| 직무 분리 (Separation of Duties) | 한 사람이 중요한 업무 전체를 처리하지 못하게 나눔 |
| 알 필요성 (Need-to-Know) | 업무상 알아야 하는 정보만 접근 허용 |
| 심층 방어 (Defense in Depth) | 여러 계층의 보안 대책을 겹쳐 적용 |

## 4. 시스템 보안

### Unix/Linux 보안

#### 계정 파일

| 파일 | 내용 |
| --- | --- |
| `/etc/passwd` | 계정 정보 (사용자명:x:UID:GID:설명:홈 디렉터리:셸). 모든 사용자가 읽을 수 있음 |
| `/etc/shadow` | **암호화된 비밀번호**와 비밀번호 정책. root만 읽을 수 있음 |

`/etc/passwd`의 두 번째 필드가 `x`이면 비밀번호가 `/etc/shadow`에 저장되어 있다는 뜻이다. UID가 0이면 root 권한을 갖는다.

#### 파일 권한

```
-rwxr-xr--   →  소유자 rwx(7), 그룹 r-x(5), 기타 r--(4)  →  754
```

| 특수 권한 | 숫자 | 표시 | 의미 | 예 |
| --- | --- | --- | --- | --- |
| SetUID | 4000 | 소유자 실행 자리에 `s` | 실행하는 동안 **파일 소유자의 권한**으로 동작 | `/usr/bin/passwd` |
| SetGID | 2000 | 그룹 실행 자리에 `s` | 실행하는 동안 파일 그룹의 권한으로 동작 | |
| Sticky Bit | 1000 | 기타 실행 자리에 `t` | 디렉터리 안의 파일은 **소유자만 삭제** 가능 | `/tmp` |

root 소유의 SetUID 파일은 공격자가 악용하면 root 권한을 얻을 수 있으므로 주기적으로 점검한다. (`find / -perm -4000`)

**umask**: 새 파일·디렉터리의 기본 권한에서 뺄 값이다. umask가 `022`이면 파일은 666 − 022 = **644**, 디렉터리는 777 − 022 = **755**가 된다.

#### 로그 파일

| 로그 | 내용 | 확인 명령 |
| --- | --- | --- |
| `utmp` | **현재 로그인**한 사용자 | `who`, `w` |
| `wtmp` | 로그인·로그아웃, 재부팅 **이력** | `last` |
| `btmp` | **로그인 실패** 기록 | `lastb` |
| `lastlog` | 사용자별 마지막 로그인 시각 | `lastlog` |
| `pacct` | 사용자가 실행한 명령어 | `lastcomm` |
| `secure` | 인증·원격 접속 관련 로그 | |
| `messages` | 시스템 전반의 로그 | |
| `xferlog` | FTP 파일 전송 기록 | |

`utmp`, `wtmp`, `btmp`는 바이너리 파일이라 `cat`이 아닌 전용 명령으로 확인한다.

### 시스템 공격

#### 버퍼 오버플로

프로그램이 할당된 버퍼보다 큰 데이터를 입력받아 **인접 메모리(복귀 주소 등)를 덮어쓰는** 공격이다. 복귀 주소를 공격자의 코드(셸코드) 위치로 바꿔 임의 코드를 실행한다.

| 대응 기법 | 내용 |
| --- | --- |
| 스택 가드 (Stack Canary) | 복귀 주소 앞에 특정 값을 두고, 함수 종료 시 값이 바뀌었으면 중단 |
| ASLR | 메모리 주소(스택·힙·라이브러리)를 실행할 때마다 **무작위**로 배치 |
| DEP / NX | 스택·힙 영역에서 **코드 실행을 금지** |
| 안전한 함수 사용 | `strcpy`, `gets`, `strcat` 대신 길이를 검사하는 `strncpy`, `fgets`, `strncat` |

#### 그 밖의 시스템 공격

- **포맷 스트링 공격**: `printf(input)`처럼 사용자 입력을 포맷 문자열로 그대로 사용하면, `%x`로 메모리를 읽고 `%n`으로 메모리에 값을 쓸 수 있다.
- **레이스 컨디션**: 프로그램이 임시 파일을 만들고 사용하는 **짧은 시간 사이**에 그 파일을 심볼릭 링크로 바꿔치기하는 공격. SetUID 프로그램이 주로 대상이다.

## 5. 네트워크 보안

### 네트워크 공격

#### 스니핑과 스푸핑

| 공격 | 내용 | 대응 |
| --- | --- | --- |
| 스니핑 | 네트워크 패킷을 엿봄. NIC를 **무차별 모드(Promiscuous Mode)**로 설정해 자기에게 오지 않은 패킷도 수신 | 암호화(SSH, HTTPS), 스위치 사용 |
| ARP 스푸핑 | 가짜 ARP 응답으로 **IP-MAC 매핑을 조작**해 트래픽을 공격자에게 유도 | **정적 ARP 테이블** (`arp -s`) |
| IP 스푸핑 | 출발지 IP를 위조. 신뢰 관계를 이용한 접속 | 신뢰 관계(rlogin 등) 제거, 출발지 필터링 |
| DNS 스푸핑 | 가짜 DNS 응답으로 공격자 사이트로 유도 | DNSSEC, `hosts` 파일 |

스위치 환경에서도 ARP 스푸핑이나 스위치 재밍(MAC 테이블을 넘치게 해 허브처럼 동작하게 함)으로 스니핑이 가능하다.

**세션 하이재킹**: 이미 인증된 TCP 세션의 시퀀스 번호를 추측·탈취해 세션을 가로챈다. 인증 이후의 세션을 빼앗으므로 OTP 같은 강한 인증도 우회된다. 대응은 암호화된 통신(SSH, TLS)이다.

#### 서비스 거부 공격 (DoS)

| 공격 | 방식 | 대응 |
| --- | --- | --- |
| Ping of Death | 허용 크기(65,535바이트)를 넘는 ICMP 패킷을 조각내 보냄 | 큰 ICMP 패킷 차단 |
| Land | **출발지 IP = 목적지 IP**로 위조한 패킷 | 출발지·목적지가 같은 패킷 차단 |
| Smurf | 출발지를 피해자로 위조한 ICMP Echo Request를 **브로드캐스트** 주소로 보냄 → 응답이 피해자에게 몰림 | 라우터에서 **Directed Broadcast 차단** |
| Teardrop | IP 단편(Fragment)의 **오프셋을 겹치게** 조작해 재조합 오류 유발 | 패치 |
| SYN Flooding | SYN만 대량으로 보내고 ACK를 보내지 않아 **Backlog 큐를 가득 채움** | **SYN Cookie**, Backlog 증가, 대기 시간 단축 |
| UDP Flooding | 대량의 UDP 패킷 전송 | 불필요한 UDP 서비스 차단 |
| Slowloris | HTTP 헤더를 **아주 느리게** 보내 연결을 오래 점유 | 연결 Timeout 설정 |

**DDoS**는 봇넷의 좀비 PC들이 동시에 공격하는 방식이다. 공격자는 마스터(C&C 서버)를 통해 에이전트(좀비)를 조종한다.

**반사·증폭 공격 (DRDoS)**: 출발지를 피해자로 위조한 작은 요청을 DNS·NTP·Memcached 같은 서버에 보내, **큰 응답**이 피해자에게 가게 한다. 실제 공격자를 추적하기 어렵다.

#### 포트 스캐닝

| 스캔 | 방식 | 열린 포트 | 닫힌 포트 |
| --- | --- | --- | --- |
| TCP Connect | 3-way handshake 완료 | 연결 성공 | RST |
| SYN (Half-open) | SYN만 보내고 SYN/ACK를 받으면 RST로 끊음. **로그가 잘 남지 않음** | SYN/ACK | RST/ACK |
| FIN / NULL / Xmas | FIN, 플래그 없음, FIN+URG+PSH를 보냄 | **응답 없음** | RST |
| UDP | UDP 패킷 전송 | 응답 없음 | ICMP Port Unreachable |

대표 도구는 **Nmap**이다.

### 보안 장비

#### 방화벽

| 종류 | 동작 계층 | 특징 |
| --- | --- | --- |

#### 침입탐지시스템 (IDS)

| 탐지 방식 | 오용 탐지 (Misuse, 시그니처 기반) | 이상 탐지 (Anomaly, 행위 기반) |
| --- | --- | --- |
| 원리 | 알려진 공격 **패턴과 일치**하면 탐지 | **정상 행위에서 벗어나면** 탐지 |
| 오탐 (False Positive) | 낮음 | **높음** |
| 새로운 공격 (제로데이) | **탐지 불가** | 탐지 가능 |
| 유지 보수 | 패턴 DB 업데이트 필요 | 정상 기준(프로파일) 학습 필요 |

| 구분 | 의미 |
| --- | --- |
| HIDS | 호스트에 설치. 시스템 로그·파일 변경 감시. 암호화된 공격도 탐지 가능 |
| NIDS | 네트워크 패킷 감시. 여러 호스트를 한 번에 감시 |
| 오탐 (False Positive) | 정상을 공격으로 판단 |
| 미탐 (False Negative) | 공격을 정상으로 판단 → **보안상 더 위험** |

- **IPS (침입방지시스템)**: 탐지뿐 아니라 **차단**까지 수행한다. 트래픽 경로(인라인)에 설치된다.
- **허니팟**: 공격자를 유인하기 위한 가짜 시스템. 공격 기법을 수집·분석한다.

#### VPN

공중망 위에 **터널링**과 암호화로 사설망처럼 쓰는 기술이다.

| 계층 | 프로토콜 |
| --- | --- |
| 2계층 | PPTP, L2F, **L2TP** |
| 3계층 | **IPSec** |
| 4계층 이상 | **SSL/TLS VPN** (웹 브라우저로 접속, 별도 클라이언트 불필요) |

### 보안 프로토콜

#### IPSec

| 프로토콜 | 기밀성 (암호화) | 무결성·인증 | 재전송 방지 |
| --- | --- | --- | --- |
| AH (Authentication Header) | **X** | O | O |
| ESP (Encapsulating Security Payload) | **O** | O (선택) | O |
| IKE | 키 교환과 **SA(보안 연관)** 협상 | | |

| 모드 | 보호 범위 | 용도 |
| --- | --- | --- |
| 전송 모드 (Transport) | IP **페이로드**만 보호. 원래 IP 헤더 유지 | 호스트 ↔ 호스트 |
| 터널 모드 (Tunnel) | **IP 패킷 전체**를 보호하고 새 IP 헤더를 붙임 | 게이트웨이 ↔ 게이트웨이 (VPN) |

AH는 IP 헤더까지 무결성을 검사하므로, 주소를 바꾸는 **NAT 환경과 충돌**한다.

#### SSL/TLS

전송 계층과 응용 계층 사이에서 동작하며, HTTPS(443)에 사용된다.

| 하위 프로토콜 | 역할 |
| --- | --- |
| Handshake | 서버 인증(인증서), 암호 알고리즘 협상, 세션 키 교환 |
| Change Cipher Spec | 협상한 암호 방식으로 전환 알림 |
| Alert | 오류·경고 전달 |
| Record | 데이터를 단편화·압축·MAC·암호화 |

핸드셰이크에서는 **공개키 암호**로 세션 키를 교환하고, 실제 데이터는 **대칭키**로 암호화한다(속도 때문).

#### 무선랜 보안

| 방식 | 암호화 | 특징 |
| --- | --- | --- |
| WEP | RC4 | 24비트 IV가 짧아 재사용됨 → **매우 취약** |
| WPA | RC4 기반 **TKIP** | WEP을 보완한 과도기 방식 |
| WPA2 | AES 기반 **CCMP** | 현재 널리 사용 |
| WPA3 | AES + **SAE** | 사전 공격(비밀번호 추측)에 강함 |

#### 이메일 보안

| 방식 | 특징 |
| --- | --- |
| PGP | 필 짐머만 개발. 인증서 대신 사용자 간 **신뢰의 웹(Web of Trust)**으로 공개키 신뢰 |
| S/MIME | **X.509 인증서(PKI)** 기반. MIME에 암호화·서명 추가 |
| PEM | IETF 표준. 구현이 복잡해 거의 쓰이지 않음 |

## 6. 애플리케이션 보안

### 웹 공격

| 공격 | 내용 | 대응 |
| --- | --- | --- |
| SQL Injection | 입력값에 SQL 구문을 넣어 DB 조회·조작 (`' OR '1'='1`) | **Prepared Statement**(바인딩 변수), 입력 검증, 최소 권한 DB 계정 |
| XSS | 게시물 등에 **스크립트**를 삽입해 **다른 사용자의 브라우저**에서 실행 (쿠키 탈취) | 출력 시 HTML 인코딩, `HttpOnly` 쿠키 |
| CSRF | 피해자가 **자기도 모르게** 공격자가 의도한 요청을 보내게 함 | CSRF 토큰, `SameSite` 쿠키, Referer 검사 |
| 파일 업로드 | 웹셸 등 실행 가능한 파일을 업로드 | 확장자 화이트리스트, 업로드 폴더 실행 권한 제거 |
| 디렉터리 트래버설 | `../`로 상위 경로의 파일 접근 | 경로 문자 필터링 |

**XSS와 CSRF 비교**: XSS는 **클라이언트(브라우저)**에서 스크립트가 실행되는 공격이고, CSRF는 피해자의 권한으로 **서버**에 위조된 요청을 보내는 공격이다.

| XSS 종류 | 내용 |
| --- | --- |
| 저장형 (Stored) | 스크립트가 게시판 등 **서버에 저장**되어 열람자마다 실행 |
| 반사형 (Reflected) | URL 파라미터의 스크립트가 응답에 **그대로 반사**되어 실행. 링크 클릭 유도 |
| DOM 기반 | 서버를 거치지 않고 브라우저의 DOM 조작으로 실행 |

### 데이터베이스 보안

| 위협 | 내용 |
| --- | --- |
| 집성 (Aggregation) | 낮은 등급의 정보를 **모아** 높은 등급의 정보를 알아냄 |
| 추론 (Inference) | 공개된 정보로부터 비밀 정보를 **유추**함 |

추론 대책: 다중 인스턴스화(Polyinstantiation), 뷰(View)로 접근 제한, 통계 결과에 잡음 추가.

## 7. 정보보호 관리

### 위험 관리

#### 위험 분석 접근법

| 접근법 | 내용 | 특징 |
| --- | --- | --- |
| 기준선 (베이스라인) | 표준화된 보안 대책 목록을 일괄 적용 | 빠르고 저렴, 조직 특성 반영 안 됨 |
| 비정형 | 전문가의 경험과 지식으로 분석 | 빠르지만 전문가 의존 |
| 상세 위험 분석 | 자산·위협·취약점을 정밀하게 분석 | 정확하지만 시간·비용이 큼 |
| 복합 | 중요한 시스템은 상세, 나머지는 기준선 | 효율적 |

#### 정량적 분석과 정성적 분석

| 구분 | 정량적 | 정성적 |
| --- | --- | --- |
| 표현 | **금액**(숫자) | 높음/중간/낮음 같은 **등급** |
| 장점 | 비용-효과 분석 가능, 객관적 | 빠르고 쉬움, 금액화 어려운 자산도 평가 |
| 기법 | 과거 자료 분석, 수학 공식, 확률 분포 | **델파이**(전문가 의견 수렴), 시나리오, 순위 결정, 퍼지 행렬 |

```
SLE (단일 손실 예상액) = 자산 가치(AV) × 노출 계수(EF)
ALE (연간 손실 예상액) = SLE × ARO (연간 발생률)
```

예) 자산 가치 1억 원, 사고 시 손실 비율 40%, 연 0.5회 발생 → SLE = 4,000만 원, ALE = **2,000만 원**. 보안 대책 비용이 연 2,000만 원보다 크면 경제성이 없다.

#### 위험 처리 전략

| 전략 | 내용 | 예 |
| --- | --- | --- |
| 위험 수용 | 위험을 받아들임 (대책 비용 > 손실) | 영향이 작은 위험 |
| 위험 감소 (완화) | 보안 대책으로 위험을 낮춤 | 방화벽, 백신 도입 |
| 위험 회피 | 위험이 있는 업무 자체를 하지 않음 | 서비스 중단 |
| 위험 전가 | 제3자에게 위험을 넘김 | **보험**, 외주 |

대책을 적용한 뒤에도 남는 위험을 **잔여 위험**이라 하며, 경영진이 이를 승인(수용)해야 한다.

### 업무 연속성 (BCP / DRP)

- **BCP (업무 연속성 계획)**: 재해 상황에서도 핵심 업무를 계속하기 위한 계획
- **DRP (재해 복구 계획)**: IT 시스템을 복구하기 위한 계획
- **BIA (업무 영향 분석)**: 업무가 중단될 때의 영향을 분석해 복구 우선순위와 목표 시간을 정함

| 지표 | 의미 |
| --- | --- |
| RTO (복구 목표 시간) | 중단 후 **얼마 안에** 복구해야 하는가 |
| RPO (복구 목표 시점) | **어느 시점의 데이터까지** 복구해야 하는가 (허용 데이터 손실량) |

| 복구 사이트 | 내용 | 복구 시간 | 비용 |
| --- | --- | --- | --- |
| 미러 사이트 | 주 센터와 같은 시스템을 **실시간 동기화**로 운영 | 즉시 | 가장 높음 |
| 핫 사이트 | 같은 장비를 갖추고 대기 (데이터는 주기적 동기화) | 수 시간 이내 | 높음 |
| 웜 사이트 | 일부 중요 장비만 갖춤 | 수일~수주 | 중간 |
| 콜드 사이트 | 공간과 전원 등 기본 설비만 갖춤 | 수주~수개월 | 가장 낮음 |

| 백업 방식 | 내용 | 복구 시 필요한 백업 |
| --- | --- | --- |
| 전체 백업 | 모든 데이터 백업 | 마지막 전체 백업 1개 |
| 차등 백업 | 마지막 **전체 백업** 이후 바뀐 데이터 | 전체 백업 + 마지막 차등 백업 |
| 증분 백업 | 마지막 **백업(종류 무관)** 이후 바뀐 데이터 | 전체 백업 + 그 이후 **모든** 증분 백업 |

### 보안 인증 제도와 평가 기준

| 제도·기준 | 내용 |
| --- | --- |
| ISMS-P | 국내 정보보호 및 개인정보보호 관리체계 인증 (KISA). 관리체계 수립·운영 16개, 보호대책 64개, 개인정보 처리 단계별 22개 → **총 102개** 인증 기준 |
| ISO/IEC 27001 | 국제 정보보호 관리체계(ISMS) 인증 표준 |
| ISO/IEC 27002 | 보안 통제 항목에 대한 실무 지침 |
| TCSEC (오렌지북) | 미국의 보안 평가 기준. D → C1 → C2 → B1 → B2 → B3 → A1 (A1이 가장 높음) |
| ITSEC | 유럽의 보안 평가 기준 |
| CC (공통평가기준) | TCSEC·ITSEC 등을 통합한 국제 표준 (**ISO/IEC 15408**). 보증 등급 **EAL1 ~ EAL7** |

CC의 구성 요소:

- **PP (보호 프로파일)**: 제품군별로 필요한 보안 요구사항 (구현과 독립적)
- **ST (보안 목표 명세서)**: 특정 제품의 보안 기능 명세 (구현에 종속적)
- **TOE (평가 대상)**: 평가받는 제품

### 디지털 포렌식

| 원칙 | 내용 |
| --- | --- |
| 정당성 | 증거는 **적법한 절차**로 수집해야 함 |
| 재현성 | 같은 조건에서 같은 결과가 나와야 함 |
| 신속성 | 휘발성 증거가 사라지기 전에 빠르게 수집 |
| 연계 보관성 (Chain of Custody) | 증거의 수집·이동·보관·분석 담당자를 **모두 기록** |
| 무결성 | 수집한 증거가 변경되지 않았음을 보장 (**해시값** 비교) |

증거 수집은 **휘발성이 높은 것부터** 한다: 레지스터·캐시 → 메모리 → 네트워크 연결·프로세스 → 디스크 → 백업 매체.

## 9. 자주 출제되는 비교 정리

| 비교 | 핵심 차이 |
| --- | --- |
| 대칭키 vs 공개키 | 같은 키·빠름·키 분배 어려움 vs 키 쌍·느림·키 분배 쉬움 |
| 기밀성 vs 전자서명에 쓰는 키 | **수신자 공개키**로 암호화 vs **송신자 개인키**로 서명 |
| MAC vs 전자서명 | 대칭키·부인방지 X vs 공개키·부인방지 O |
| DES vs AES | 64비트 블록·56비트 키·Feistel vs 128비트 블록·128/192/256비트 키·SPN |
| RSA vs DH vs ECC | 소인수분해 vs 이산대수(키 교환) vs 타원곡선 이산대수(짧은 키) |
