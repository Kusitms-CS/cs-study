# 4주차 - Network

## 공통 키워드

### 1. OSI 7계층

OSI(Open Systems Interconnection)는 네트워크 통신 과정을 7개의 계층으로 나눠서 설명하는 모델이다.

#### 7계층 구조

| 계층 | 이름 | 설명 |
| --- | --- | --- |
| 7 | 응용 계층(Application layer) | 사용자가 네트워크 서비스를 직접 사용하는 계층. HTTP, DNS, SMTP 같은 프로토콜을 다룬다 |
| 6 | 표현 계층(Presentation layer) | 데이터의 형식과 표현 방식을 담당. 인코딩/디코딩, 암호화/복호화, 압축/압축 해제 등을 처리 |
| 5 | 세션 계층(Session layer) | 두 컴퓨터 사이의 통신 세션(연결, 대화 상태)을 관리. 통신 시작/유지/종료, 중단 시 복구 등을 담당 |
| 4 | 전송 계층(Transport layer) | 데이터를 목적지까지 제대로 전달하는 것을 담당. 데이터 크기, 전달 확인, 순서 관리, 오류 처리 등을 수행. 대표 프로토콜: TCP, UDP |
| 3 | 네트워크 계층(Network layer) | 데이터를 목적지까지 어떤 경로로 전달할지 담당. IP가 이 계층에서 동작 |
| 2 | 데이터 링크 계층(Data Link layer) | 동일한 네트워크 안에서 연결된 장치 사이의 데이터 전달을 담당. MAC 주소로 장치를 구분 |
| 1 | 물리 계층(Physical layer) | 데이터를 실제 물리적인 신호(전기, 빛, 전파, 케이블 등)로 전달하는 계층 |

#### 헷갈리는 것만 정리

- 4계층: 데이터 전달 자체를 관리
- 3계층: 목적지까지의 경로를 결정
- 2계층: 바로 연결된 장치 사이에서 전달


### 2. TCP/IP 4계층

TCP/IP는 인터넷 통신을 4개의 계층(응용, 전송, 인터넷, 네트워크 접근)으로 나눠서 보는 모델로, OSI 7계층을 더 크게 묶어놓은 형태이다.

| 계층 | 이름 | 설명 |
| --- | --- | --- |
| 4 | 응용 계층(Application layer) | 애플리케이션이 네트워크를 통해 데이터를 주고받는 방식을 정의. 대표 프로토콜: HTTP/HTTPS, DNS, SMTP, FTP |
| 3 | 전송 계층(Transport layer) | 출발지 애플리케이션에서 목적지 애플리케이션까지 데이터를 전달. TCP, UDP가 이 계층에 해당 |
| 2 | 인터넷 계층(Internet layer) | 데이터를 목적지까지 전달하기 위한 경로와 주소를 담당. IP 주소를 이용해 여러 네트워크를 거쳐 전달. IP, ICMP가 이 계층에 해당 |
| 1 | 네트워크 접근 계층(Network Access layer) | 실제로 데이터를 네트워크에 전달하는 방법을 담당. Ethernet, Wi-Fi 등이 여기 해당 |

#### 7계층과 비교하면

- 7계층의 7, 6, 5 → 4계층의 4
- 7계층의 4 → 4계층의 3
- 7계층의 3 → 4계층의 2
- 7계층의 2, 1 → 4계층의 1

로 단순화되었다고 생각하면 된다.


### 3. IP

IP는 데이터를 목적지 컴퓨터까지 전달하기 위해 컴퓨터를 식별하고, 데이터가 이동할 경로를 결정하는 통신 규칙이다.

- 쉽게 말해, 인터넷에서 컴퓨터의 주소를 찾아서 데이터를 전달하는 역할을 한다.

#### IP 주소

- 네트워크에서 장치를 식별하기 위한 주소이다.
- 현재 주로 IPv4(32비트) 형식이 사용되고 있으며, 주소 부족 문제를 해결하기 위해 IPv6(128비트)가 점점 도입되고 있다.

#### 라우팅

- 목적지까지 데이터를 어떤 경로로 보낼지 결정하는 과정이다.
- IP는 데이터를 목적지까지 전달하는 것 자체만 담당할 뿐, 데이터가 제대로 도착했는지는 보장하지 않는다.
  - 데이터가 제대로 도착했는지 확인하고 보장하는 역할은 TCP가 담당한다.


### 4. TCP / UDP

TCP와 UDP는 둘 다 전송 계층에서 데이터를 전달하기 위해 사용하는 프로토콜이다.

#### TCP

- 데이터가 정확하고 순서대로 전달되도록 확인하며 통신하는 프로토콜이다.
- 정확한 데이터 전달이 중요한 경우 사용한다.

#### UDP

- 데이터 전달을 확인하지 않고 빠르게 전송하는 프로토콜이다.
- 속도와 실시간성이 중요한 경우 사용한다.

#### TCP vs UDP

| 구분 | 특징 |
| --- | --- |
| TCP | 연결 지향, 순서 보장, 신뢰성 높음, 상대적으로 느림 |
| UDP | 비연결형, 순서 미보장, 신뢰성 낮음, 상대적으로 빠름 |


### 5. 3-way / 4-way Handshake

TCP(연결을 맺고 통신하는 연결 지향형 프로토콜)에서 연결을 맺고 끊는 과정이다.

- TCP는 데이터를 보내기 전에 서로 통신할 준비가 되었는지 확인하고 연결을 설정한다.
- 참고로 UDP는 연결 없이 바로 데이터를 보내는 비연결형 프로토콜이기 때문에 아래 개념이 적용되지 않는다.

#### 3-way Handshake (연결 설정)

3번 주고받는다고 해서 3-way Handshake라고 부른다.

| 순서 | 메시지 | 방향 | 설명 |
| --- | --- | --- | --- |
| 1 | SYN | 클라이언트 → 서버 | 연결 요청 |
| 2 | SYN + ACK | 서버 → 클라이언트 | 연결 요청 확인 + 연결 준비 완료 |
| 3 | ACK | 클라이언트 → 서버 | 서버의 응답 확인 → TCP 연결 설정 완료 |

#### 4-way Handshake (연결 종료)

통신이 끝나면 TCP 연결을 바로 끊는 게 아니라, 서로 통신이 끝났는지 확인하며 4번 주고받아 연결을 종료한다.

| 순서 | 메시지 | 방향 | 설명 |
| --- | --- | --- | --- |
| 1 | FIN | 클라이언트 → 서버 | 연결 종료 요청 |
| 2 | ACK | 서버 → 클라이언트 | 연결 종료 요청 확인 |
| 3 | FIN | 서버 → 클라이언트 | 연결 종료 요청 |
| 4 | ACK | 클라이언트 → 서버 | 연결 종료 요청 확인 → TCP 연결 종료 |


### 6. DNS

DNS(Domain Name System)는 도메인 이름을 IP 주소로 변환해주는 시스템이다.

- 사람은 읽기 쉬운 도메인 이름을 사용하지만, 컴퓨터는 IP 주소를 이용해 통신하기 때문에 DNS가 이를 변환해주는 역할을 한다.


### 7. Port

Port는 한 컴퓨터에서 실행 중인 여러 프로그램을 구분하여 데이터를 전달하기 위한 번호이다.

- IP가 컴퓨터를 찾는 주소라면, Port는 그 컴퓨터 안에서 어떤 프로그램으로 데이터를 보낼지 구분해준다.
