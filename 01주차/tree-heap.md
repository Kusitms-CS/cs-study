# 비선형 구조

계층적이지만 일렬로 나열되지 않은 자료 구조. 부모-자식, 연결, 소속 등의 관계를 가진다.

## Tree

### 용어 정리

- node (정점, 데이터)
  - root node
  - parent node
  - child node
  - sibling node
  - leaf node
- sub-tree, edge (간선)
- 일반 트리 : 자식 노드를 0~n개 가질 수 있음
- 이진 트리 : 자식 노드를 최대 2개 가질 수 있음
- external node (외부 노드, 단말 노드) : 자식 노드가 없는 경우
- internal node (비단말 노드, 내부 노드, 가지 노드) : 자식 노드가 있는 경우
- depth : 루트 노드부터 해당 노드까지 이어지는 간선의 개수
- height : 해당 노드에서 leaf node까지 가장 긴 경로상의 간선 개수
- 균형 트리 : 높이 차이가 한정된 트리, 검색/삽입의 시간 복잡도 유지 가능
- 불균형 트리 : 서브트리의 높이 차이가 크게 나는 경우 (예: pure 연결 리스트)

### 이진 트리

- 각 노드는 키, 값, 왼쪽 노드, 오른쪽 노드로 이루어져 있음
- 오른쪽 자식 > 부모 > 왼쪽 자식
- 불균형할 수도 있음
- 효율적인 검색 & 높이가 낮을수록 탐색 시간이 빠름

사용처

- 검색 알고리즘
- 정렬 알고리즘 (이진 탐색 트리 활용 & 힙의 우선순위 큐)
- 데이터 압축
- 파일 시스템
- 게임 개발
- DB (B+tree를 자주 사용함)

```java
Set<String> set = new TreeSet<>();
// 중복값을 허용하지 않음. add를 사용할 수 있음

Map<String, Integer> map = new TreeMap<>();
// 트리맵은 이진탐색트리를 활용하여 저장하므로 정렬, 검색에 유용하다.
// put과 keySet() 메서드를 사용할 수 있음 (데이터 삽입, 출력)
```

### 이진 트리 종류

- Full binary tree (정 이진 트리) : 모든 노드가 자식을 0개 또는 2개만 가짐 (1개인 노드가 없음)
- Perfect Binary Tree (포화 이진 트리) : 모든 레벨이 꽉 차 있고, 모든 리프 노드의 depth가 동일함. 노드 수는 항상 `2^h - 1`개
- Complete Binary Tree (완전 이진 트리) : 마지막 레벨을 제외한 모든 레벨이 채워져 있고, 마지막 레벨은 왼쪽부터 순서대로 채워짐 (힙이 이 구조를 사용)
- Skewed Binary Tree (편향 이진 트리) : 모든 노드가 한쪽 자식만 가져 사실상 연결 리스트처럼 동작 → 탐색/삽입이 O(n)까지 악화될 수 있음
- Balanced Tree (균형 이진 트리) : 왼쪽/오른쪽 서브트리의 높이 차이가 일정 범위(보통 1) 이내로 유지되도록 스스로 재조정하는 트리. AVL Tree, Red-Black Tree가 대표적이며, 높이를 O(log n)으로 보장해 탐색 성능을 유지한다
- Binary Heap : 완전 이진 트리 + 힙 속성(부모-자식 우선순위 관계)을 만족하는 트리. 배열로 구현하는 것이 일반적

참고: https://adjh54.tistory.com/324

**해시가 트리보다 좋은 경우**

- 단일 검색 : 해시는 키를 기반으로 값을 직접 찾기 때문에 트리보다 검색 속도가 훨씬 빠르다. 데이터가 많을수록 좋은 성능을 보인다.
- 간단한 구현 : 해시는 트리보다 구현이 비교적 간단하다.

**해시가 트리보다 나쁜 경우**

- 순서 제한 : 해시는 데이터의 순서를 보장하지 않는다 (정렬되지 않음).
- 범위 검색 : 트리는 특정 범위 검색에서 좋은 성능을 보이지만, 해시는 그렇지 못하다.
- 데이터 분포 : 데이터가 고르게 분포되지 않으면 특정 버킷에 데이터가 집중되어 검색 성능이 저하될 수 있다.

## Heap

참고: https://coding-factory.tistory.com/603 (priority queue)

힙(Heap)은 특정한 순서에 따라 정렬된 요소를 저장하는 트리 기반 자료구조로, 힙 구조를 가진 이진 트리이다. 일반적으로 이진 힙(binary heap)으로 구현되며, 우선순위 큐(priority queue)와 같은 추상 자료형을 구현할 때 주로 사용된다.

힙의 특징

1. 완전 이진 트리 (Complete Binary Tree) : 마지막 레벨을 제외한 모든 레벨이 완전히 채워져 있고, 마지막 레벨은 왼쪽부터 채워지는 형태
2. 부모-자식 노드 관계 : 부모 노드는 항상 자식 노드보다 우선순위가 높거나 같다. 최대 힙(max heap)은 부모가 자식보다 크거나 같고, 최소 힙(min heap)은 부모가 자식보다 작거나 같다.
3. 힙 속성 : 모든 부모-자식 쌍이 위 조건을 만족해야 한다.

힙이 지원하는 연산

1. 삽입 (Insertion) : 새로운 요소를 추가한다. 우선순위 큐에서는 우선순위에 따라 삽입된다.
2. 삭제 (Deletion) : 가장 우선순위가 높은 요소를 삭제한다. 최대 힙은 가장 큰 요소, 최소 힙은 가장 작은 요소가 삭제된다.

- 삽입 및 삭제가 빠르고 (O(log n)) 우선순위 기반 처리가 가능하다는 장점
- 임의 접근이 아닌 순차 탐색은 O(n) 시간이 소요된다는 단점
- 정렬 유지로 인한 오버헤드
- 배열 기반의 힙은 공간을 미리 할당해야 한다는 단점

```java
PriorityQueue<Integer> minHeap = new PriorityQueue<>();
// offer를 활용한 추가
// peek를 통한 확인
// poll을 통한 삭제
```
