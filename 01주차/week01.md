# 1주차 - 자료구조 / 시간복잡도

## 공통 키워드

### 1. Big-O

Big-O는 알고리즘의 시간 복잡도나 공간 복잡도를 표현하는 방법이다.

입력 크기 `n`이 커질수록 알고리즘의 실행 시간이 어떻게 증가하는지를 나타낸다.

#### 주요 Big-O

| Big-O | 이름 | 설명 |
| --- | --- | --- |
| `O(1)` | 상수 시간 | 입력 크기와 관계없이 일정한 시간 |
| `O(log n)` | 로그 시간 | 입력 크기가 증가해도 실행 횟수가 천천히 증가 |
| `O(n)` | 선형 시간 | 입력 크기에 비례하여 증가 |
| `O(n log n)` | 선형 로그 시간 | `n`과 `log n`을 곱한 형태 |
| `O(n²)` | 제곱 시간 | 입력 크기의 제곱에 비례하여 증가 |
| `O(2ⁿ)` | 지수 시간 | 입력이 증가할수록 실행 시간이 급격하게 증가 |
| `O(n!)` | 팩토리얼 시간 | 입력이 증가할수록 실행 횟수가 매우 크게 증가 |

#### Big-O 계산 시 주의할 점

- Big-O에서는 정확한 실행 시간보다 입력 크기에 따른 증가율을 중요하게 본다.
- 상수 제거
  - `O(2n)` → `O(n)`
  - `O(100n)` → `O(n)`
- 작은 항 제거
  - `O(n + 10)` → `O(n)`
  - `O(n² + n)` → `O(n²)`
- 가장 빠르게 증가하는 항을 기준으로 표현한다.


### 2. Array

Array는 여러 데이터를 순서대로 저장하는 자료구조이다.

각 데이터는 Index(인덱스)를 가지고 있어 원하는 위치의 데이터를 빠르게 가져올 수 있다.

#### 특징

- 데이터의 순서가 존재한다.
- Index를 통해 특정 요소에 접근할 수 있다.
- Index를 이용한 접근이 빠르다.
- 중간에 데이터를 삽입하거나 삭제하면 이후 요소를 이동해야 할 수 있다.

#### 주요 연산 시간복잡도

| 연산 | 시간복잡도 | 설명 |
| --- | --- | --- |
| 인덱스 접근 | `O(1)` | 특정 인덱스의 요소에 접근 |
| 검색 | `O(n)` | 처음부터 순차적으로 탐색 |
| 마지막 삽입 | `O(1)` 평균 | 마지막에 요소 추가 |
| 마지막 삭제 | `O(1)` | 마지막 요소 제거 |
| 중간 삽입 | `O(n)` | 이후 요소 이동 필요 |
| 중간 삭제 | `O(n)` | 이후 요소 이동 필요 |


### 3. LinkedList

LinkedList는 Node들이 서로 연결되어 있는 자료구조이다.

각 Node는 데이터를 가지고 있고, 다음 Node를 가리킨다.

#### 특징

- 여러 개의 Node가 연결되어 있다.
- 데이터가 메모리에 연속적으로 저장될 필요가 없다.
- 특정 위치에 접근하려면 Node를 순차적으로 탐색해야 한다.
- Node의 위치를 알고 있다면 삽입과 삭제가 빠르다.

#### 주요 연산 시간복잡도

| 연산 | 시간복잡도 |
| --- | --- |
| 특정 위치 접근 | `O(n)` |
| 검색 | `O(n)` |
| 맨 앞 삽입 | `O(1)` |
| 맨 앞 삭제 | `O(1)` |
| 특정 Node 삽입 | `O(1)`* |
| 특정 Node 삭제 | `O(1)`* |

`*` 해당 Node의 위치 또는 참조를 이미 알고 있다는 전제이다.


### 4. Stack

Stack은 LIFO(Last In, First Out) 방식으로 데이터를 처리하는 자료구조이다.

→ 마지막에 들어온 데이터가 가장 먼저 나온다.

#### 주요 연산

| 연산 | 설명 | 시간복잡도 |
| --- | --- | --- |
| `push` | 데이터 추가 | `O(1)` |
| `pop` | 가장 최근 데이터 제거 | `O(1)` |
| `peek` | 가장 최근 데이터 확인 | `O(1)` |

#### 활용 예시

- 함수 호출 스택
- 브라우저 뒤로 가기
- Undo / Redo
- 괄호 검사
- DFS(깊이 우선 탐색)


### 5. Queue

Queue는 FIFO(First In, First Out) 방식으로 데이터를 처리하는 자료구조이다.

→ 먼저 들어온 데이터가 가장 먼저 나온다.

#### 주요 연산

| 연산 | 설명 | 시간복잡도 |
| --- | --- | --- |
| `enqueue` | 데이터 추가 | `O(1)` |
| `dequeue` | 가장 오래된 데이터 제거 | `O(1)` |
| `peek` | 가장 오래된 데이터 확인 | `O(1)` |

#### 활용 예시

- 작업 대기열
- 프린터 작업
- 메시지 처리
- 이벤트 처리
- BFS(너비 우선 탐색)


### 6. Hash Table

Hash Table은 Key와 Value를 한 쌍으로 저장하는 자료구조이다.

Key를 해시 함수에 넣으면 데이터를 저장할 위치를 빠르게 찾을 수 있다.

예를 들어 `이름 → 전화번호`처럼 데이터를 관리할 수 있다.

#### 주요 연산

| 연산 | 평균 | 최악 |
| --- | --- | --- |
| 삽입 | `O(1)` | `O(n)` |
| 검색 | `O(1)` | `O(n)` |
| 삭제 | `O(1)` | `O(n)` |

→ Key를 이용하면 데이터를 빠르게 찾을 수 있다.

#### Collision

서로 다른 Key가 같은 저장 위치를 가지게 되는 경우를 Collision(충돌)이라고 한다.

충돌이 발생하면 다른 방법으로 데이터를 저장해야 한다.

대표적인 방법:

- Chaining
  - 같은 위치에 여러 데이터를 연결해서 저장

- Open Addressing
  - 다른 빈 공간을 찾아서 저장

#### 활용 예시

- 캐시
- 중복 검사
- 빠른 데이터 조회
- Key-Value 데이터 관리


### 7. Tree

Tree는 데이터를 계층적인 구조로 저장하는 자료구조이다.

#### 주요 용어

| 용어 | 설명 |
| --- | --- |
| Root | Tree의 가장 위에 있는 Node |
| Parent | 특정 Node의 상위 Node |
| Child | 특정 Node의 하위 Node |
| Leaf | 자식 Node가 없는 Node |
| Edge | Node와 Node를 연결하는 간선 |
| Depth | Root에서 특정 Node까지의 거리 |
| Height | Tree의 최대 깊이 |

#### 특징

- 계층적인 데이터를 표현하기 좋다.
- Node와 Edge로 구성된다.
- Root를 기준으로 부모-자식 관계를 가진다.
- 다양한 형태의 Tree가 존재한다.

#### 대표적인 Tree

- Binary Tree
- Binary Search Tree
- Heap
- Trie

#### 활용 예시

- 파일 시스템
- HTML DOM
- 조직도
- 카테고리 구조
- 메뉴 구조


### 8. Heap

Heap은 우선순위가 높은 데이터를 빠르게 찾기 위한 자료구조이다.

완전 이진 트리 형태로 구성된다.

#### 종류

- Min Heap
  - 부모 Node의 값이 자식 Node보다 작거나 같다.
  - 가장 작은 값이 Root에 위치한다.

- Max Heap
  - 부모 Node의 값이 자식 Node보다 크거나 같다.
  - 가장 큰 값이 Root에 위치한다.

#### 주요 연산

| 연산 | 시간복잡도 |
| --- | --- |
| 최솟값/최댓값 확인 | `O(1)` |
| 삽입 | `O(log n)` |
| 삭제 | `O(log n)` |
| Heap 생성 | `O(n)` |

#### 활용 예시

- Priority Queue
- 작업 스케줄링
- Heap Sort
- 최단 경로 알고리즘
- 최솟값/최댓값 지속 관리
