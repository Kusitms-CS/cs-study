## Big-O

> EX) "데이터가 10배로 늘어나면 처리 시간은 몇 배가 될까?"를 나타내는 척도. 전화번호부에서 이름을 찾는다고 생각해보면,
> - 몇 페이지인지 미리 알고 바로 펼치면 → `O(1)`
> - 절반씩 넘기며 찾으면(사전 찾기처럼) → `O(log n)`
> - 처음부터 한 장씩 다 넘기면 → `O(n)`

알고리즘의 성능(시간/공간 복잡도)을 입력 크기 `n`에 대한 함수로 나타내는 표기법.

| 표기 | 의미 | 예시 |
|---|---|---|
| `O(1)` | 입력 크기와 무관하게 일정 | 배열 인덱스 접근 |
| `O(log n)` | 처리 범위가 절반씩 감소 | 이진 탐색 |
| `O(n)` | 입력 크기에 비례 | 배열 순회 |
| `O(n log n)` | 효율적인 정렬 | 병합 정렬, 퀵 정렬(평균) |
| `O(n²)` | 이중 반복문 | 버블 정렬 |
| `O(2ⁿ)` / `O(n!)` | 완전 탐색, 브루트포스 | 부분집합 생성, 순열 |

## Array (배열)

> EX)  영화관 좌석처럼 번호가 매겨진 자리들이 나란히 줄지어 있는 것. 좌석 번호(인덱스)만 알면 바로 앉을 수 있지만, 중간에 한 명을 끼워 앉히려면 뒷사람들이 전부 한 자리씩 옮겨야 한다.

동일한 크기의 데이터를 **연속된 메모리 공간**에 저장하는 자료구조.

| 연산 | 시간복잡도 | 비고 |
|---|---|---|
| 접근 (index) | `O(1)` | 메모리 주소를 계산해 바로 접근 |
| 탐색 | `O(n)` | 처음부터 순회해야 함 |
| 삽입/삭제 (맨 끝) | `O(1)` | |
| 삽입/삭제 (중간/맨 앞) | `O(n)` | 뒤(또는 앞) 요소들을 한 칸씩 밀어야 함 |


---

## LinkedList (연결 리스트)

>EX) 보물찾기 게임의 힌트 쪽지들. 각 쪽지는 "다음 힌트는 어디 있다"는 정보만 담고 있어서, 처음부터 순서대로 따라가야만 원하는 쪽지를 찾을 수 있다. 대신 중간에 새 힌트를 끼워넣는 건 쉽다 — 앞뒤 쪽지의 연결(포인터)만 바꿔주면 된다.

각 노드가 데이터와 다음(또는 이전) 노드에 대한 **포인터/참조**를 가지는 자료구조. 메모리상 연속적이지 않아도 된다.

| 연산 | 시간복잡도 | 비고 |
|---|---|---|
| 접근 | `O(n)` | 인덱스로 바로 접근 불가, 순차 탐색 필요 |
| 탐색 | `O(n)` | |
| 삽입/삭제 | `O(1)`* | *위치를 이미 알고 있을 때 (포인터만 변경) |

- 종류: 단일 연결 리스트(Singly), 이중 연결 리스트(Doubly), 원형 연결 리스트(Circular)
- 배열과 비교: 임의 접근이 느린 대신 삽입/삭제가 빠름 → 사용 패턴에 따라 선택

## Stack (스택)

> EX) 접시를 쌓아 올리는 것. 새 접시는 맨 위에 올리고(push), 뺄 때도 맨 위 것부터 뺀다(pop). 맨 아래 접시를 꺼내려면 위에 쌓인 걸 다 치워야 한다.

**LIFO(Last In First Out)** 구조. 마지막에 넣은 데이터가 가장 먼저 나옴.

| 연산 | 설명 | 시간복잡도 |
|---|---|---|
| `push` | 삽입 | `O(1)` |
| `pop` | 삭제 | `O(1)` |
| `peek` | 최상단 조회 | `O(1)` |

- 배열 또는 연결 리스트로 구현 가능


---

##  Queue (큐)

>EX) 편의점 계산대 줄. 먼저 줄을 선 사람이 먼저 계산하고 나간다. 새치기(중간 삽입) 없이 뒤로만 붙고 앞에서만 빠져나간다.

**FIFO(First In First Out)** 구조. 먼저 넣은 데이터가 먼저 나옴.


\* 배열로 구현 시 앞쪽 삭제는 `O(n)`이 될 수 있어, 보통 **원형 큐(circular buffer)** 나 연결 리스트로 구현해 `O(1)`을 달성한다.

**변형**
- **Deque(Double-ended Queue)**: 양쪽 끝에서 삽입/삭제 가능
- **Priority Queue**: 우선순위가 높은 요소가 먼저 나옴 (보통 Heap으로 구현)

## Hash Table (해시 테이블)

> EX) 옷 보관소의 사물함. "이름"을 말하면 계산기(해시 함수)가 바로 몇 번 칸인지 알려줘서, 처음부터 뒤질 필요 없이 곧장 그 칸으로 간다. 가끔 두 사람이 같은 번호를 받으면(충돌), 그 칸에 옷을 여러 개 걸어두거나 다른 빈 칸을 찾아준다.

**Key를 해시 함수로 변환한 값(해시값)을 인덱스로 사용**해 데이터를 저장/조회하는 자료구조.

| 연산 | 평균 | 최악 |
|---|---|---|
| 삽입 | `O(1)` | `O(n)` |
| 삭제 | `O(1)` | `O(n)` |
| 탐색 | `O(1)` | `O(n)` |

> 최악의 경우는 해시 충돌이 많이 발생했을 때 나타난다.

**해시 충돌 해결 방법**
- **Chaining**: 같은 인덱스에 연결 리스트(또는 트리)로 여러 값을 연결
- **Open Addressing**: 충돌 시 다른 빈 슬롯을 탐색 (Linear/Quadratic Probing, Double Hashing)

좋은 해시 함수는 충돌을 최소화하고 값을 고르게 분산시켜야 한다. 활용 예: Java `HashMap`, JS `Map`/`Object`, 캐시, 중복 체크

## Tree (트리)

> EX)  회사 조직도. 팀장 아래 팀원들이 있고, 그 팀원 아래에 또 다른 사람이 있을 수 있는 위아래 관계 구조. 이진 탐색 트리(BST)는 "왼쪽엔 나보다 작은 값, 오른쪽엔 나보다 큰 값"

노드와 간선으로 이루어진 **계층적(비선형)** 자료구조. 사이클이 없는 그래프의 일종


- **이진 트리(Binary Tree)**: 각 노드가 최대 2개의 자식을 가짐
- **이진 탐색 트리(BST)**: 왼쪽 서브트리 < 부모 < 오른쪽 서브트리

| 트리 종류 | 탐색/삽입/삭제 |
|---|---|
| BST (일반) | 평균 `O(log n)`, 편향 시 최악 `O(n)` |
| AVL / Red-Black Tree (균형) | 항상 `O(log n)` 보장 |

- 순회(Traversal): 전위(Pre-order), 중위(In-order), 후위(Post-order), 레벨 순회(BFS)
- 활용 예: 파일 시스템, DB 인덱스(B-Tree/B+Tree), DOM 트리

## Heap (힙)

> EX) 조직도인데 딱 하나의 규칙만 지키는 버전 — "부모는 항상 자식보다 높은(또는 낮은) 값". 형제 사이의 순서는 상관없다. 그래서 제일 크거나(또는 작은) 값은 항상 맨 꼭대기에 있어 바로 꺼낼 수 있다.

**완전 이진 트리** 기반으로, 부모-자식 간 특정 우선순위 조건을 항상 만족하는 자료구조.

- **Max Heap**: 부모 노드 값이 항상 자식보다 크거나 같음 → 루트가 최댓값
- **Min Heap**: 부모 노드 값이 항상 자식보다 작거나 같음 → 루트가 최솟값
- BST와 달리 **좌우 순서 규칙은 없음**, 오직 부모-자식 대소 관계만 유지
- 배열로 구현 가능 (인덱스 `i`의 자식은 `2i+1`, `2i+2`)

| 연산 | 시간복잡도 |
|---|---|
| 삽입 | `O(log n)` |
| 삭제 (루트 제거) | `O(log n)` |
| 최댓값/최솟값 조회 | `O(1)` |

활용 예: Priority Queue 구현, 힙 정렬(Heap Sort), 다익스트라 알고리즘

## Backend 심화 (선택)

### Java Collection Framework

> EX) 공구함. List, Set, Map이라는 표준 규격(인터페이스)의 서랍이 있고, 그 안에 상황별로 골라 쓸 수 있는 여러 도구(ArrayList, HashSet, HashMap 등)가 들어있다. 어떤 도구를 쓰든 서랍 이름(인터페이스)만 알면 꺼내 쓰는 방법은 똑같다.

자바에서 자료구조를 다루기 위해 제공하는 **인터페이스 + 구현체** 표준 라이브러리.

| 인터페이스 | 특징 | 대표 구현체 |
|---|---|---|
| `List` | 순서 O, 중복 O | `ArrayList`, `LinkedList` |
| `Set` | 순서 X, 중복 X | `HashSet`, `LinkedHashSet`, `TreeSet` |
| `Map` | Key-Value, Key 중복 X | `HashMap`, `LinkedHashMap`, `TreeMap` |
| `Queue` | FIFO(일부는 우선순위) | `LinkedList`, `PriorityQueue` |

```java
List<String> list = new ArrayList<>();   // 순서 유지, 중복 허용
Set<String> set = new HashSet<>();       // 중복 자동 제거
Map<String, Integer> map = new HashMap<>(); // key-value 저장
```

- "이메일 중복 없이 저장하고 싶다" → `Set` 선택

- "회원가입 순서대로 저장하고 싶다" → `List` 또는 `LinkedHashSet` 선택

### HashMap 내부 구조

> EX) 위 Hash Table 사물함 비유의 실제 구현체. 한 칸(버킷)에 옷이 너무 많이 몰리면(충돌 8개 이상) 그 칸을 뒤죽박죽 쌓아두는 대신 "정리된 서랍(트리)"으로 바꿔서 더 빨리 찾게 하고, 사물함 전체가 꽉 차기 시작하면 resize

`HashMap`은 내부적으로 **배열(버킷) + 연결 리스트(또는 트리)** 로 구성된다.

1. `key.hashCode()`로 해시값을 계산해 배열의 인덱스(버킷 위치)를 정한다.
2. 같은 인덱스에 값이 이미 있으면(충돌) 연결 리스트로 이어 붙인다. (Chaining)
3. **Java 8부터**: 한 버킷에 노드가 8개 이상 쌓이고 배열 크기가 64 이상이면, 연결 리스트를 **레드-블랙 트리**로 전환 → 최악의 탐색 성능이 `O(n)` → `O(log n)`으로 개선.
4. 기본 용량은 16, `load factor`는 0.75. 저장된 요소 수가 `용량 × 0.75`를 넘으면 배열 크기를 2배로 늘리고 기존 데이터를 재배치(**rehashing**)한다.

```java
Map<String, Integer> map = new HashMap<>();
map.put("apple", 1);   // "apple".hashCode() → 버킷 인덱스 계산 → 저장
map.get("apple");      // 같은 방식으로 인덱스 계산 → 바로 조회, 평균 O(1)
```

### ConcurrentHashMap

> EX) 사물함 보관소 전체에 문이 하나뿐이라 한 번에 한 사람만 들어갈 수 있는 `Hashtable`과 달리, `ConcurrentHashMap`은 사물함을 여러 구역으로 나눠 구역별로 자물쇠를 따로 걸어둔다. 그래서 다른 사람들이 동시에 다른 구역을 이용할 수 있다.

멀티스레드 환경에서 안전하게 사용할 수 있도록 만든 `HashMap`의 동시성 버전.


- `HashMap`은 `null` key/value를 허용하지만, `ConcurrentHashMap`은 **허용하지 않는다** (여러 스레드가 동시에 접근할 때 `null`이 "값이 없다"는 뜻인지 "아직 다른 스레드가 쓰는 중"이라는 뜻인지 구분할 수 없기 때문).
- 활용 예: 여러 요청이 동시에 캐시나 카운터를 읽고 쓰는 서버 환경 (조회수 카운트, 세션 캐시 등)
