# 8주차 - JavaScript 핵심 개념

### 1. Execution Context (실행 컨텍스트)

JavaScript 코드가 **실행되는 환경 정보를 담은 객체**이다. 엔진은 코드를 실행하기 전에 먼저 실행 컨텍스트를 만들고, 그 안에서 코드를 실행한다.

#### 종류

| 종류 | 설명 |
| --- | --- |
| Global Execution Context | 프로그램이 시작될 때 **가장 먼저 1개** 생성됨 |
| Function Execution Context | 함수가 **호출될 때마다** 새로 생성됨 |

#### 구성 요소

| 구성 요소 | 설명 |
| --- | --- |
| Variable Environment | 변수, 함수 선언 정보를 저장 |
| Lexical Environment | 식별자와 값을 매핑하고, **바깥 환경에 대한 참조**를 가짐 → Scope Chain의 기반 |
| This Binding | `this`가 가리킬 대상 |

#### 생성 과정

1. **생성 단계 (Creation Phase)**
   - 변수와 함수 선언을 메모리에 먼저 등록한다. (→ Hoisting)
   - Scope Chain을 결정한다.
   - `this` 값을 결정한다.
2. **실행 단계 (Execution Phase)**
   - 코드를 위에서 아래로 실행하면서 값을 할당하고 함수를 호출한다.

#### Call Stack (콜 스택)

- 실행 컨텍스트가 쌓이는 **LIFO(후입선출)** 구조의 스택이다.
- 함수를 호출하면 컨텍스트가 스택에 쌓이고, 함수가 끝나면 스택에서 제거된다.
- JavaScript는 **싱글 스레드**이기 때문에 콜 스택은 하나뿐이고, 가장 위에 있는 컨텍스트만 실행된다.

> Scope, Hoisting, this는 모두 실행 컨텍스트가 만들어지는 과정에서 결정되는 값이다. 그래서 이후 개념의 기반이 된다.


### 2. Scope (스코프)

변수에 **접근할 수 있는 유효 범위**이다. 변수를 어디에서 선언했는지에 따라 어디까지 사용할 수 있는지가 달라진다.

#### 종류

| 종류 | 설명 |
| --- | --- |
| Global Scope | 코드 어디에서나 접근 가능 |
| Function Scope | 함수 내부에서만 접근 가능 (`var`) |
| Block Scope | `{ }` 블록 내부에서만 접근 가능 (`let`, `const`) |

#### Scope Chain (스코프 체인)

- 변수를 찾을 때 **현재 스코프 → 바깥 스코프 → 전역 스코프** 순서로 탐색한다.
- 전역까지 찾아도 없으면 `ReferenceError`가 발생한다.
- 안쪽 스코프에서는 바깥 변수를 볼 수 있지만, 바깥에서는 안쪽 변수를 볼 수 없다.

#### Lexical Scope (렉시컬 스코프)

- 스코프는 함수를 **어디서 호출했는지**가 아니라 **어디서 선언했는지**에 따라 결정된다.
- JavaScript는 렉시컬 스코프를 따르기 때문에, 코드를 작성하는 시점에 변수 탐색 경로가 이미 정해진다.
- 호출 시점에 스코프가 결정되는 방식은 Dynamic Scope라고 하며, JavaScript는 해당하지 않는다.

#### var / let / const

| 구분 | var | let | const |
| --- | --- | --- | --- |
| 스코프 | 함수 | 블록 | 블록 |
| 재선언 | 가능 | 불가 | 불가 |
| 재할당 | 가능 | 가능 | 불가 |
| 호이스팅 시 상태 | `undefined`로 초기화 | TDZ | TDZ |

- `var`는 블록(`if`, `for`)을 무시하고 함수 전체를 스코프로 삼기 때문에 의도치 않게 변수가 새어 나갈 수 있다.
- 기본적으로 `const`를 사용하고, 재할당이 필요한 경우에만 `let`을 사용하는 것이 권장된다.

> 스코프는 "변수를 어디서 찾을 수 있는가"에 대한 규칙이고, 이 규칙은 선언 위치로 정해진다.


### 3. Hoisting (호이스팅)

실행 컨텍스트의 생성 단계에서 **선언이 먼저 메모리에 등록되어**, 선언문보다 앞에서도 해당 식별자를 사용할 수 있는 것처럼 보이는 현상이다.

- 코드가 실제로 위로 이동하는 것이 아니라, **선언만 먼저 처리되는 것**이다.
- 값의 할당은 원래 코드 위치에서 실행 단계에 이루어진다.

#### 선언 방식별 동작

| 대상 | 선언 전에 접근하면 | 설명 |
| --- | --- | --- |
| `var` | `undefined` | 선언과 동시에 `undefined`로 초기화됨 |
| `let` / `const` | `ReferenceError` | 선언은 등록되지만 초기화 전이라 접근 불가 (TDZ) |
| 함수 선언문 | 정상 호출 | 함수 전체가 먼저 등록됨 |
| 함수 표현식 | 변수 규칙을 따름 | `var`로 선언하면 `undefined`라서 호출 시 `TypeError` |

#### TDZ (Temporal Dead Zone, 일시적 사각지대)

- `let`, `const`가 스코프 시작부터 **선언문이 실행되기 전까지**의 구간을 말한다.
- 이 구간에서 변수에 접근하면 에러가 발생한다.
- 즉 `let`, `const`도 호이스팅은 되지만, TDZ 때문에 호이스팅되지 않는 것처럼 보일 뿐이다.

```js
console.log(a); // undefined
var a = 1;

console.log(b); // ReferenceError (TDZ)
let b = 1;
```

#### 정리

- 함수 선언문과 변수 선언이 겹치면 **함수 선언이 우선**한다.
- 호이스팅으로 인한 예기치 못한 동작을 피하려면 `var` 대신 `let`, `const`를 쓰고, 변수는 사용하기 전에 선언한다.

> 호이스팅은 JavaScript의 특별한 기능이 아니라, 실행 컨텍스트가 선언을 먼저 등록하기 때문에 생기는 부수 효과이다.


### 4. Closure (클로저)

함수가 **자신이 선언된 시점의 렉시컬 환경을 기억**해서, 그 함수가 바깥 스코프 밖에서 실행되더라도 바깥 변수에 접근할 수 있는 현상이다.

- 보통 함수 실행이 끝나면 지역 변수는 사라진다.
- 하지만 내부 함수가 바깥 함수의 변수를 참조하고 있으면, 바깥 함수가 종료된 후에도 해당 변수는 **GC(Garbage Collection) 대상에서 제외되어 유지**된다.

```js
function makeCounter() {
  let count = 0;
  return () => ++count;
}

const counter = makeCounter();
counter(); // 1
counter(); // 2
```

#### 왜 필요할까?

- 전역 변수를 쓰지 않고도 **함수 호출 간에 상태를 유지**할 수 있다.
- 외부에서 직접 접근할 수 없는 **private 변수**를 만들 수 있다. (데이터 은닉)

#### 활용

| 용도 | 설명 |
| --- | --- |
| 데이터 은닉 | 변수를 외부에서 직접 수정하지 못하게 하고, 함수를 통해서만 접근하도록 함 |
| 상태 유지 | 카운터, 캐시, 메모이제이션 등 |
| 함수 팩토리 / 커링 | 설정값을 기억하는 함수를 만들어 반환 |
| 콜백 / 이벤트 핸들러 | 선언 시점의 값을 기억한 채로 나중에 실행됨 |

#### 주의할 점

- **반복문 + `var`**: `var`는 함수 스코프라서 반복문 안의 콜백이 모두 같은 변수를 참조하게 된다. (예: `setTimeout`에서 모두 마지막 값이 출력됨) `let`을 사용하면 반복마다 새로운 블록 스코프가 생겨 해결된다.
- **메모리 누수**: 더 이상 필요 없는 클로저가 큰 객체를 계속 참조하면 메모리가 해제되지 않는다. 사용이 끝나면 참조를 해제해야 한다.

> 클로저는 별도의 문법이 아니라 렉시컬 스코프와 함수가 값처럼 전달될 수 있다는 특성이 합쳐져 나타나는 현상이다.


### 5. this

함수가 **호출될 때 결정되는, 실행 중인 함수의 주체(대상 객체)**를 가리키는 키워드이다.

- 스코프가 **선언 위치**로 결정되는 것과 달리, `this`는 **호출 방식**에 따라 결정된다.
- 같은 함수라도 어떻게 호출하느냐에 따라 `this`가 달라진다.

#### 호출 방식별 this

| 호출 방식 | this |
| --- | --- |
| 일반 함수 호출 | 전역 객체 (`strict mode`에서는 `undefined`) |
| 메서드 호출 (`obj.fn()`) | 메서드를 호출한 객체 (점 `.` 앞의 객체) |
| 생성자 호출 (`new Fn()`) | 새로 생성되는 인스턴스 |
| `call` / `apply` / `bind` | 명시적으로 지정한 객체 |
| 화살표 함수 | 자신의 `this`가 없고, **바깥 스코프의 `this`**를 그대로 사용 |

#### call / apply / bind

| 메서드 | 동작 | 인자 전달 |
| --- | --- | --- |
| `call` | `this`를 지정하고 **즉시 실행** | 인자를 하나씩 전달 |
| `apply` | `this`를 지정하고 **즉시 실행** | 인자를 배열로 전달 |
| `bind` | `this`가 고정된 **새 함수를 반환** (실행 X) | 인자를 하나씩 전달 |

#### 자주 겪는 문제

- 메서드를 변수에 꺼내 담거나 **콜백으로 넘기면** 점(`.`) 앞의 객체가 사라져서 `this`를 잃어버린다.
- 해결 방법
  - `bind`로 `this`를 고정한다.
  - 화살표 함수를 사용해 바깥 `this`를 유지한다.
- 객체의 메서드를 **화살표 함수로 정의하면** `this`가 객체가 아니라 바깥 스코프를 가리키므로 주의해야 한다.

#### 일반 함수 vs 화살표 함수

| 구분 | 일반 함수 | 화살표 함수 |
| --- | --- | --- |
| this 결정 시점 | 호출할 때 | 선언할 때 (바깥 스코프) |
| call / apply / bind로 변경 | 가능 | 불가능 |
| 생성자(`new`)로 사용 | 가능 | 불가능 |

> 스코프는 "선언된 위치", `this`는 "호출된 방식"으로 결정된다. 이 차이를 구분하는 것이 핵심이다.


### 6. Prototype (프로토타입)

JavaScript는 **프로토타입 기반 언어**로, 객체가 다른 객체를 **상속(위임)** 받아 속성과 메서드를 공유하는 구조이다.

- 모든 객체는 자신의 부모 역할을 하는 객체(프로토타입)를 가리키는 숨겨진 링크 `[[Prototype]]`을 가진다.
- 객체에서 속성을 찾을 때 자신에게 없으면 프로토타입을 따라가며 찾는다.

#### 용어 정리

| 용어 | 설명 |
| --- | --- |
| `prototype` | **함수 객체**만 가지는 속성. 이 함수로 `new` 생성한 인스턴스의 부모가 됨 |
| `__proto__` | **모든 객체**가 가지는 링크. 실제 부모 프로토타입을 가리킴 (`Object.getPrototypeOf()` 사용 권장) |
| `constructor` | 프로토타입 객체가 **자신을 만든 생성자 함수**를 가리키는 속성 |

```
instance.__proto__ === Constructor.prototype
Constructor.prototype.constructor === Constructor
```

#### Prototype Chain (프로토타입 체인)

- 속성을 찾을 때 **자기 자신 → 부모 프로토타입 → 그 상위 프로토타입 → ... → `Object.prototype` → `null`** 순서로 탐색한다.
- 끝까지 찾지 못하면 `undefined`를 반환한다.
- 배열, 함수 등 모든 객체에서 `toString()` 같은 메서드를 쓸 수 있는 이유가 `Object.prototype`까지 체인이 연결되어 있기 때문이다.

#### 왜 필요할까?

- 메서드를 생성자 안에서 정의하면 인스턴스마다 함수가 새로 만들어진다.
- 메서드를 `prototype`에 정의하면 모든 인스턴스가 **하나의 함수를 공유**하므로 메모리를 절약할 수 있다.

#### 속성 확인 방법

| 방법 | 설명 |
| --- | --- |
| `hasOwnProperty()` | 객체 **자신**이 가진 속성인지 확인 (프로토타입 제외) |
| `in` 연산자 | 프로토타입 체인 **전체**에서 속성이 있는지 확인 |

#### class와 프로토타입

- ES6의 `class`는 새로운 상속 방식이 아니라, 프로토타입 기반 상속을 **쉽게 쓰도록 감싼 문법(Syntactic Sugar)**이다.
- `class` 내부에 정의한 메서드는 결국 `prototype`에 등록되고, `extends`는 프로토타입 체인을 연결한다.

#### Scope Chain vs Prototype Chain

| 구분 | Scope Chain | Prototype Chain |
| --- | --- | --- |
| 탐색 대상 | **변수** | 객체의 **속성, 메서드** |
| 연결 기준 | 코드를 작성한 위치 (렉시컬 환경) | `[[Prototype]]` 링크 |
| 탐색 방향 | 안쪽 스코프 → 바깥 스코프 → 전역 | 자신 → 부모 → ... → `null` |
| 실패 시 | `ReferenceError` | `undefined` |

> 이름은 비슷하지만 서로 다른 체인이다. 하나는 변수를, 다른 하나는 객체의 속성을 찾는 데 사용된다.


### 7. 개념 간 관계 정리

| 개념 | 한 줄 요약 | 결정되는 시점 / 기준 |
| --- | --- | --- |
| Execution Context | 코드가 실행되는 환경 | 함수 호출 시 생성 |
| Scope | 변수의 유효 범위 | 코드를 **작성한 위치** (렉시컬) |
| Hoisting | 선언이 먼저 등록되는 현상 | 실행 컨텍스트 **생성 단계** |
| Closure | 선언 당시의 환경을 기억하는 함수 | 렉시컬 스코프 + Scope Chain |
| this | 함수를 호출한 주체 | 함수를 **호출한 방식** |
| Prototype | 객체 간 상속 구조 | `[[Prototype]]` 링크 |

- 함수가 호출되면 **실행 컨텍스트**가 생성되고, 이 과정에서 선언 등록(**Hoisting**), 변수 탐색 경로(**Scope Chain**), **this**가 함께 결정된다.
- **Closure**는 렉시컬 스코프 덕분에 함수가 선언된 환경을 기억하는 것이다.
- 변수는 **Scope Chain**, 객체의 속성은 **Prototype Chain**으로 찾는다.
