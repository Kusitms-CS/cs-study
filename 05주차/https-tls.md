# HTTPS / TLS

## HTTPS

- 인터넷에서 하이퍼텍스트를 교환하기 위한 통신 규약.
- 80번 포트를 사용한다
- TCP/IP 위에서 작동함(인터넷이니까 ㅎㅎ..)

### HTTP와 HTTPS의 차이

- 암호화가 되지 않은 평문 데이터를 전송하는 프로토콜인 HTTP의 단점을 해결하기 위해 HTTPS가 도입됨
- Hyper Text Transfer Protocol Secure
- 443번 포트를 사용한다.

### 대칭키와 비대칭키 암호화

- 대칭키 암호화와 비대칭키 암호화 둘다 HTTPS에서 사용되는 방식이다.
- https 연결과정(핸드셰이크)에서는 세션키를 교환한다. 
  - 세션키는 대칭키이며, 빠른 연산속도를 필요로 하므로 도입된 결정이다.
  - 세션키의 교환과정에서 비대칭키가 사용된다. 연결의 성립 시에 안전하게 세션키를 공유하기 위해 도입된 결정이다.
- 정리하면..

1. 클라가 서버로 연결시도
2. 서버가 공개키를 브라우저에게 전달
3. 브라우저가 유효성 검증, 세션키(대칭키) 발급
4. 브라우저가 세션키 보관, 서버의 공개키로 세션키를 암호화하여 서버로 전송
5. 서버는 개인키로 / 암호화된 세션키를 / 복호화하여 세션키를 얻음
6. 클라와 서버는 동일한 세션키를 공유하므로, 이후 데이터 전달 시 세션키로 암호화 및 복호화 진행

#### 대칭키 암호화

- 클라와 서버가 동일한 키를 사용하여 암호화와 복호화를 진행
- 키가 노출되면 위험하지만 연산 속도가 빠름



#### 비대칭키 암호화

- 1개의 쌍으로 구성된 공개키 - 개인키를 암호화 - 복호화하는데에 사용함
- 키가 노출되어도 비교적 안전하나 연산 속도가 느림
- 공개키
  - 모두에게 공개 가능한 키
- 개인키
  - 개인이 소유한 키
- 암호화를 공개키로/개인키로 하는지에 따라 효과가 달라진다
  - 공개키 암호화 : 개인키로만 복호화가 가능하다
  - 개인키 암호화 : 공개키로 복호화가 가능하다. 내가 인증한 정보이므로 신뢰성을 보장하는 효과가 있다.



### 인증서와 CA

- 서버가 클라와 세션키를 공유하기 위해서는 공개키를 생성해야 한다.
- 공개키를 생성할때 Certificate Authority, 인증된 기관인 CA에 공개키를 전송하여 인증서를 발급받게 된다.

1. 윤지는 HTTPS를 적용하기 위해 공개키와 개인키를 발급하였음
2. 윤지는 CA 기업에 돈을 내고 공개키를 저장하기 위한 인증서를 발급 요청함
3. CA는 CA사의 이름, 서버의 공개키, 서버 정보를 기반으로 인증서를 생성하고, CA사의 개인키로 암호화하여 윤지에게 인증서를 제공
4. 윤지는 클라에게 암호화된 인증서를 제공함
5. 브라우저는 CA사의 공개키를 미리 갖고있기 때문에, 암호화된 인증서를 복호화함
6. 암호화된 인증서를 복호화해서 얻은 윤지의 공개키로 세션키를 공유함

- 흠...
  - 인증서는 CA의 개인키로 암호화되어 신뢰성을 확보가능함
    - 인증서 내부에는 윤지의 공개키가 포함되어 있음 (발급 목적)
  - 클라는 윤지의 공개키로 데이터를 암호화하였으므로 그것만 복호화하면 원본 데이터를 얻을 수 있음
  - 물론 암호화 복호화 과정이 들어가서 HTTPS가 HTTP보다 속도가 느리지만 현재는 거의 체감할 수 없는 수준으로 차이가 미미하다

## TLS

[https://docs.tosspayments.com/resources/glossary/tls](https://docs.tosspayments.com/resources/glossary/tls)

- 데이터를 안전하게 주고받기 위한 암호화 프로토콜이며, TLS가 적용된 HTTP = HTTPS
- SSL, Secure Sockets Layer는 초기 버전이며 Transport Layer Security가 더 범용적으로 사용되고 있음 (혼동되는 경우가 잦음)
- 인증
  - CA의 인증서로 상대 서버의 정보를 확인 가능함
- 암호화
  - 대칭, 비대칭 암호화 조합을 사용한 암호화
- 무결성
  - 데이터 손실 및 변조를 통신과정에서 방지. MAC, 메시지 인증코드를 사용하여 데이터를 검증함



### TLS 핸드셰이크

- TCP 핸드셰이크 성립 이후에 TLS 핸.셰가 시작되고 .. 최초 1회만 발생함. 동일 세션 내에는 일어나지 않음
- API call, DNS 쿼리 등의 HTTPS를 사용하는 경우마다 TLS 핸드셰이크가 발생함
