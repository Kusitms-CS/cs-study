# Virtual Memory / Paging / Page Fault

## Virtual Memory
메인 메모리의 캐시로 동작하게끔 하여 (메인메모리를 2차 저장장치의 캐시로 사용하는 기술)
프로그램끼리 메인 메모리를 공유할 수 있도록,
제한된 메인 메모리에서 프로그래밍해야 하는 제약을 없애기 위한 기술

## Paging
논리적 주소를 동일한 크기로, 물리적 주소를 동일한 크기로 잘라 hole이 발생하지 않도록 하는 방법
- 가상 기억장치를 같은 크기의 블록으로 편성
  - 논리적 메모리 블록은 page
  - 물리적 메모리 블록은 frame
- hole이 프로세스 영역 외부에 생겨 발생하는 외부 단편화를 해결할 수 있음
- 프로세스가 page size로 나누어지지 않는 경우의 내부 단편화는 해결 불가능
  - 하지만, 외부 단편화가 더 치명적인 경향 (내부 단편화의 max hole size는 pagesize-1이기 때문에)

### Page Table
- page와 frame을 매핑하여 연속적인 것처럼 이어주는 기술
- 페이지 테이블을 참조하여, 논리주소 > 물리주소로 변환하여 접근
  - 주소 변환(address translation) 또는 주소 사상(address mapping)
    - 가상 주소(virtual address) = 가상 페이지 번호(virtual page number) + 페이지 변위(page offset)
- 해당 과정에서 TLB(translation lock aside buffer) : 페이지 테이블을 위한 하드웨어 캐시를 사용하여 페이징 성능 완화

- 특징
  - 주소 변환을 MMU에서 맡아 하므로 + 연속된 논리주소를 독립적으로 사용하는 효과로 사용시 편리함
  - 프레임단위의 비연속적 메모리 할당으로 동적할당, 외부 단편화도 문제 없음
  - 내부 단편화 발생 가능
  - 각 프로세스마다 페이지테이블을 가짐
    - 프로세스 switch 시의 재설정이 일어나므로 context switching의 overhead가 존재함

## Page Fault
가상 페이지의 유효비트가 0인 경우 page fault가 발생하여 운영체제가 제어를 넘겨받음
운영체제는 이후 다음 계층(플래시 메모리 or 자기디스크 등..)을 찾아서 해당 페이지를 메인메모리의 어느 공간에 넣을지를 결정해야 함

가상 메모리에서 page fault를 처리할 때 소모되는 자원이 많음.
보통 크기 페이지인 경우에는 첫 워드를 꺼내는데에 걸리는 시간이 오래걸리기 때문에 가상 메모리를 설계하는데에 있어 중요한 요소
- 접근시간 보상을 위해 페이지가 충분히 커야함
- page fault 발생률을 줄이기 위해 page를 fully associative(가상페이지가 어떤 실제페이지로도 사상되도록)한 방식으로 메인메모리에 배치
- page fault는 소프트웨어로, 좋은 알고리즘을 사용하여 보완할 수 있음
- 가상 메모리에서 write through 방식을 사용하면 시간 소요가 많이 되므로 write back을 사용함

## Page Replacement
page fault 발생시, 메인메모리의 모든 페이지가 사용중인 경우 교체가 일어남
- 발생확률을 최대한 줄이기 위해 LRU(least recently used) 방식을 사용하여 가장 오래된 페이지를 교체하는 방식을 사용함. 교체된 페이지는 2차 메모리의 swap space에 사용됨
- reference bit를 두어, 페이지가 접근될때마다 해당 값을 1로 바꾸는 유사 LRU 방식을 사용함. 주기적으로 0으로 만들어서 특정 시간동안 얼마나 많이 접근되었는지를 알 수 있게 함
